# Decisions and assumptions

Every assumption made while building is logged here, newest last, so judges and
teammates can see why the code looks the way it does.

## Phase 1: skeleton, ingestion, replay

| # | Decision | Why |
| --- | --- | --- |
| D1 | Feature scope = all **Must** (F1-F12) + **S1, S3, S4, S7**, per the plan's recommendation in section 13. | No feature ticks were supplied; the plan recommends this set as fitting the 60 h budget. |
| D2 | Reddit is read through public **RSS** (`/r/<sub>/new/.rss`), not `.json`. | On 2026-10-04 the `.json` listings returned HTTP 403 without OAuth; RSS returned 200. Still keyless. |
| D3 | GDELT DOC 2.0 API is configured but its replay twin is empty for now. | It returned HTTP 429 (rate limit, <= 1 req / 5 s) during recording. GKG 15-minute files (which also carry original-language titles via the translingual stream) cover GDELT. Will re-record. |
| D4 | GDELT GKG titles come from the `<PAGE_TITLE>` element of the Extras column, HTML-unescaped. Article bodies are **not** scraped. | GKG has no body text; fetching 1,000s of pages per 15 min would be slow, fragile and raises copyright concerns. Headline-level NLP is the norm for news-signal work. |
| D5 | GKG rows are kept only if they carry a finance/risk theme (ECON_, EPU_, sanctions, conflict, disaster, cyber ...). | Cuts ~25% of off-topic rows before NLP; the event classifier's "Other/Non-event" class handles what slips through. |
| D6 | GKG rows are joined to the same window's **Events** export by URL to obtain CAMEO root code, Goldstein scale, NumMentions/NumSources/NumArticles and action geography. | The impact model's GDELT features (plan section 6) and the CAMEO 14-20 -> Geopolitical weak labels need them. |
| D7 | Replay re-dates docs to *now* on emission (original time kept in `meta.original_published_at`), paced by original gaps / speed with a 2 s clamp; docs that share one timestamp (a GDELT file) are spread evenly across the window. | Keeps "live" views live in an offline demo; no multi-minute dead air; no 500-doc bursts. |
| D8 | Replay loops get new doc ids (`<id>~r<lap>`). | Idempotent downstream stores (signal id = hash(doc, entity, model)) would otherwise drop every lap after the first. |
| D9 | While a live source's breaker is open, the runner serves that source's replay twin ("fallback" mode) and retries live after the back-off. | "A failing source never blocks others" and the dashboard never goes quiet. |
| D10 | Tweets: `StephanAkkerman/stock-market-tweets-data` (Hugging Face), busiest day **2020-07-13**, originals with a cashtag, first 6,000 by time. | X has no free keyless API. This set has real per-second timestamps (the ticker-tagged `mjw/stock_market_tweets` set only has dates, so it is used for impact/backtest instead). |
| D11 | The in-process bus drops a slow subscriber's *oldest* message rather than blocking producers; drops are counted on `/v1/health`. | Back-pressure from a slow dashboard socket must never stall ingestion. |
| D12 | The Makefile and Dockerfile set `PYTHONPATH=src` explicitly instead of relying only on the editable install. | On macOS, files under an iCloud-synced `~/Documents` can be flagged *hidden*; Python 3.11+ skips hidden `.pth` files, which breaks `pip install -e .` imports. |
| D13 | Financial PhraseBank is CC BY-NC-SA 3.0 (non-commercial). | Fine for a hackathon prototype; flagged so any commercial follow-up swaps the training data. |
| D14 | `docker compose --profile prod` starts Redpanda/TimescaleDB/Redis, but the engine adapters for them (plan item C1, a *Could*) are not built. | Kept honest in the compose file comments; the demo profile is the supported path. |
| D15 | Added `doc_id`, `geo` and `impact.mode` to the signal schema beyond the plan's example. | `doc_id` links a signal to its evidence; `geo` feeds the world map and country-targeted shocks; `impact.mode` makes "heuristic mode" visible per signal. |

## Phase 2: NLP engine

| # | Decision | Why |
| --- | --- | --- |
| D16 | Repo `VIT_YughJuneja_Hackathon` (github.com/yugh88; VIT Bhopal, Yugh Juneja). | Planned as `vitbhopal-yughjuneja-hackathon`; the owner created the remote under this name. |
| D17 | Models are trained locally on Apple-Silicon MPS (user approved); the same scripts run on Colab via `src/training/notebooks/train_all_colab.ipynb`. | No GPU quota needed; one code path. |
| D18 | Runtime inference uses **onnxruntime + tokenizers only** (INT8 dynamic quantisation). PyTorch/transformers are training-only (`requirements-train.txt`). | Keeps the Docker image small and the demo CPU-only. |
| D19 | `trafilatura` and spaCy NER are **not** used. | We never fetch article HTML (D4), so boilerplate removal is moot; linking is gazetteer-driven, so NER could only add unlinked names. Both saved ~100 MB. |
| D20 | fastText via `fasttext-numpy2-wheel`. | The official `fasttext` wheel calls `np.array(copy=False)`, which NumPy 2 rejects. |
| D21 | SEntFiN comes from the Hugging Face mirror `temetnosce01/phrasebank_and_sentfin` (7,843 entity-tagged headlines). | The original is on Kaggle, which needs an API key. Licence: research use per the SEntFiN paper. |
| D22 | Sentiment input is `<entity> [SEP] <sentence>` for every row; document-level rows use an empty entity. | One format for train and inference; SEntFiN and FiQA teach the entity slot. |
| D23 | English sentiment starts from `ProsusAI/finbert`, whose head is permuted to our label order rather than re-initialised. **Caveat:** FinBERT was itself fine-tuned on Financial PhraseBank, so PhraseBank test scores may be optimistic; the twitter test set is uncontaminated. | Stated in the model card next to the numbers. |
| D24 | Topic->event mapping is keyword-sharpened: "Company / Product News" becomes Product Launch only with launch/approval words (else Other); "Treasuries / Corporate Debt" becomes Credit Event only with default/downgrade words. | The raw topic is a grab-bag; without this, Product Launch would absorb a quarter of all tweets. |
| D25 | Weak event labels come from **English** GDELT headlines only (700 random 15-min windows, 2023-2026, 606k articles -> 13.1k labelled), with strict regexes or theme + keyword, plus SEC 8-K item codes. Multilingual event data comes from translating those rows with NLLB. | Theme-only labels on non-English titles were spot-checked and found too noisy (e.g. a Korean police-day story labelled Cyber). Spot-check precision of the English rules is roughly 70-80%; no reported metric uses weak labels. |
| D26 | Event classifier confidence < 0.55 blends 50/50 with zero-shot NLI (mDeBERTa XNLI); structured evidence (single 8-K item class, CAMEO 18-20 with Goldstein <= -9) overrides a model guess below 0.8 confidence. | Plan section 5; filings and GDELT codes are more reliable than a weak model guess. |
| D27 | GDELT location fallback (doc -> sovereign) only fires for Geopolitical, Macroeconomic and Credit events; sovereigns co-mentioned with a company are dropped unless the event is one of those. | Without this, every local crime story with a US dateline became a "United States" signal. |
| D28 | Impact uses the documented **heuristic** (`engine/impact/heuristic.py`, `impact.mode="heuristic"`) until the learned model lands in Phase 3. | The plan's fallback path, made visible per signal. |
| D29 | "Run both sentiment paths and average" is applied when language ID confidence < 0.5, not to GDELT translations. | GDELT's translingual GKG gives English *themes* but not an English *title*, so there is no English twin text to score. |
| D30 | Quantisation is chosen **per model, on data**: export measures full dynamic INT8 against FP32 on 256 validation inputs and keeps it only if argmax agreement >= 98% and mean abs probability difference <= 0.02; otherwise only the embedding table is quantised. Measured: FinBERT full INT8 agreement 0.89 (accuracy 0.87 -> 0.85 on 400 val rows; per-channel, reduce-range and const-B-only variants did no better), mDeBERTa-XNLI 0.46; embedding-only 1.00 / 0.997. | The plan assumed INT8 is free. On these fine-tuned models it costs ~2 accuracy points, so accuracy wins over size; latency is measured in Phase 3 `bench.py`. Static (calibrated QDQ) quantisation is the follow-up if latency targets are missed. |
| D31 | Sentiment calibration is a single **linear scale** (least squares onto FiQA train scores), not isotonic. FiQA val MSE: raw 0.356, isotonic 0.053 (but only 43 distinct output levels), linear 0.050. | Same accuracy, smooth output (no ties between very different headlines). Consequence: calibrated scores rarely exceed |0.45|, matching FiQA's human scale; Module A's kappa slider absorbs the scale. |
| D32 | Event classifier base is **XLM-RoBERTa-base**, not mDeBERTa-v3-base. The zero-shot NLI fallback stays mDeBERTa-XNLI (embedding-only INT8, 538 MB). | DeBERTa-v3 under INT8 loses most of its output contrast (D30); the NLI model only runs on low-confidence docs, so its size/speed matter less. |
| D33 | After quantisation, large float32 weight matrices are stored as **float16 + Cast** (ONNX Runtime folds the Cast at load, so compute stays float32). | Halves file size with no accuracy cost: measured argmax agreement 1.0 on every model (sentiment-multi 535 -> 364 MB, FinBERT 367 -> 196 MB, NLI 538 -> 366 MB). Full INT8 was rejected on labelled data: XLM-R sentiment accuracy 0.854 -> 0.825 on 800 multilingual val rows. |
| D34 | XLM-R fine-tunes freeze the 250k-token input embedding table (192M of 278M params) and pad batches to multiples of 32. | Without this, training used 16 GB and swapped on an 18 GB Mac (Adam state for the embeddings, plus one MPS graph per sequence length). Freezing embeddings is standard for cross-lingual transfer and keeps the multilingual alignment intact. |
| D35 | Zero-shot NLI runs in `/v1/analyze` by default but not on the stream (`SENTINEL_ZERO_SHOT_STREAM=true` enables it). | ~0.45 s/doc on CPU would make the stream fall behind at 30x replay. |
| D36 | Sovereign signals require a Geopolitical, Macroeconomic or Credit event. A GDELT location *alone* qualifies only with corroboration: CAMEO root 15/16/17/19/20 with abs(Goldstein) >= 5 and >= 2 sources, or a >= 0.9-confidence macro/credit call on an ECON-themed article carried by several outlets. Central banks (Fed, BoE, BoJ, PBOC, RBI) are aliases of their sovereign. | Replay review found local stories becoming sovereign alarms (a Kansas small-business fraud -> "US Credit Event, impact 8"), which would fire Module B's stress test. |

## Phase 3: impact, aggregation, outputs, evaluation

| # | Decision | Why |
| --- | --- | --- |
| D37 | Fine-tuned models are distributed as **GitHub Release assets** of this repo (user decision). `data/reference/models_manifest.json` (committed) lists each archive's size and SHA-256; `python -m engine.models_download` resumes interrupted downloads over HTTP Range, shows a progress bar and refuses a checksum mismatch. The zero-shot NLI model is `lazy`: fetched in the background the first time a low-confidence event needs it. | Keyless, no extra account, and the default first-run download is smaller. |
| D38 | **Sentiment scale: the two requirements conflict, so the score map is switchable.** Requirement A: FiQA MSE within +0.01 of the FiQA-faithful map. Requirement B: 40 clearly strong headlines reach abs(score) >= 0.7 and 20 neutral ones stay <= 0.2. Of 3,465 candidate monotone maps (power x intensity-cue x scale), **none** satisfies both, for either model. FiQA's human ratings are compressed (median abs 0.39) and the classifiers give its moderate headlines the same raw signal as clearly strong news. Published default: the `range` map (passes B; FiQA test MSE reported). `SENTINEL_SENTIMENT_SCALE=human` restores the FiQA-faithful linear map. Both maps, the grid and the per-headline check scores are stored in each model's `sentinel.json` and summarised in the model card. **Open for the user to decide.** | Module A needs real tilt and the spec says -1..1, but hiding the FiQA cost would be dishonest. |
| D39 | The sentiment *score* uses the **untempered** P(pos)-P(neg); temperature scaling only sets *confidence*. | Phase 2 fitted the scale on untempered values but applied it to tempered ones, a silent mismatch found while doing D38. |
| D40 | Calibration is fitted on **FiQA val only**. | Both sentiment models were fine-tuned with FiQA train rows; fitting there flattered the numbers (train+val linear MSE 0.032 vs val 0.050). |
| D41 | Impact model: **scikit-learn HistGradientBoosting** (point model on log(1+z), plus 10%/90% quantile models), not LightGBM. Drivers are **occlusion attributions** (prediction drop when one feature is reset to its training median), not TreeSHAP. | LightGBM's macOS wheel needs Homebrew `libomp`, which failed to install here (unrelated untrusted Homebrew tap) and would add a setup step for every Mac user. scikit-learn ships its own OpenMP. |
| D42 | Impact training data: one GDELT 15-minute English window per weekday, 2019-01-02 to 2026-08-31, alternating 14:30 / 20:30 UTC (in session / after the US close): 2,000 windows, 111,769 entity-linked headlines, re-linked and scored by the shipped pipeline. Prices: yfinance (231 of 233 tickers; BK failed to download, and TATAMOTORS.NS was renamed after its 2025 demerger). | The plan's "GDELT history joined with prices"; a window per weekday covers every regime at ~16 GB streamed, nothing large stored. |
| D43 | No-look-ahead rules in code: d0 = first trading day whose close can reflect the news (local close by exchange; after-close -> next day); beta from the 120 trading days before d0; sigma from the 60 days before d0; price features use data strictly before d0. Sovereigns: max(abs(index move), abs(VIX change)) / sigma60. Test split by time: train 2019-2023, tune on 2023, test 2024+. | Plan section 6 and the user's Phase 3 rules; unit-tested in `tests/test_aggregate.py`. |
| D44 | Stream features (burst, novelty, outlets) come from one `EntityActivity` class for both training and serving. Its burst baseline uses the windows it actually observed, which on a continuous stream is every window. | Training sees one sampled window per day; a calendar baseline would be almost all zeros there and non-zero live, a train/serve skew. |
| D45 | `S_e(t)` adds a neutral prior weight `w0 = 1` to the decayed weighted mean. | It shrinks thin evidence toward 0 and makes S decay to 0 when news stops (the plan's "stale-signal decay"); a plain weighted mean is invariant to uniform decay and would freeze. |
| D46 | Signals live in memory (cursor-paginated API) and are written to `data/output/signals.jsonl` plus hourly Parquet; DuckDB is the query tool over those files rather than a separate store. | Same "file + DuckDB" outcome as the plan with one less moving part; idempotent by signal id. |
| D47 | One NLP pipeline per process (`get_pipeline`), with stream state reset when an app starts; the NLP worker uses `asyncio.timeout`, not `wait_for`. | Re-creating ONNX sessions per app deadlocked the test suite, and on Python 3.11 `wait_for` can swallow a cancellation, which hung shutdown. |
| D48 | Ambiguous acronyms removed from the gazetteer after an audit of 30k GDELT titles: ABC (ABC News), USB, PMI, CRM, CAT, SA, RI and others; two-letter aliases only US, UK, EU. | "Agricultural Bank of China" had matched 2,565 headlines, mostly ABC News. |
| D49 | Weak labels and topic mapping send price-move + earnings-word headlines ("shares slump after loss", "beats estimates") to Earnings/Guidance; 31 native Hindi finance sentences (`data/train_extra/hindi_finance_idioms.csv`, written for training only and **not reviewed by a native speaker**) are added, oversampled x4, to the multilingual sentiment training data. The evaluator asserts that no training-only text appears in any eval set. | User's low-priority item 6. |
| D50 | GDELT DOC API: HTTP 429 now triggers a 15-minute (or Retry-After) cool-down instead of repeated breaker failures; in replay mode the source reports "covered by gdelt_gkg". | It never answered during recording; the GKG/Events files carry the same articles. |
| D51 | The multilingual test set (`data/eval/multilingual_to_label.csv`, 300 GDELT headlines x 10 languages, translingual windows from 2025-06 to 2026-08) is **left unlabelled for a human**; NLLB English translations sit beside each headline as a reading aid. Until labelled, the model card reports the translated-PhraseBank numbers, marked as a proxy. | User instruction: our models must not label their own test set. |
| D52 | The impact target is **kind-adjusted**: log(1+z) centred on each entity kind's 2019-2023 median (equity, bank, corporate, sovereign). Headline metrics use the same adjusted z; rho against raw z is also reported. The first model (raw z) scored test rho 0.150, but half of that was the sovereign/company level difference created by the two label definitions (sovereign median z 1.13 vs equity 0.84); kind-adjusted rho is 0.074. | The raw model rated routine sovereign items ("Auction of 91-day Treasury bills") impact 9, which would fire Module B's stress test. The adjusted number is the honest measure of what the text adds. |
| D53 | Impact range = interquartile range of realised outcomes (same 1-10 scale) among training signals with the same predicted score, replacing quantile models. | Quantile predictions mapped onto point-prediction deciles always gave "1-10". The empirical range is honest and interpretable ("10 (5-10)"). |
| D54 | Novelty compares against an entity's 300 most recent docs in 72 h, not all of them. | Unbounded history made novelty quadratic for busy entities (found by `make bench`); sampled training history never exceeds 300, so train and serve stay consistent. |
| D55 | ONNX Runtime transformer graph fusion was tried for speed: no gain (24.8 vs 24.8 docs/s on FinBERT), because ORT already fuses at session load. Not adopted. | Measured, per the user's throughput item. |

| D63 | Loan PD stress: the systemic factor is the position's spread shock in units of the **1-year** spread volatility (PDs are 1-year), capped at 3.09; the stressed PD is **PD + V(z) - V(0)**, where V is the Vasicek conditional PD. | D64 | Module B capital: IRB RWA on the stressed PDs (PD migration), CET1 starts at 12% of the book's own RWA, and losses = MTM + new provisions. Derivative counterparty RWA is not modelled. | Transparency about what drives the capital number. |
